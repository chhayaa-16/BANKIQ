To verify that the feature values generated by Python (`generator/labels.py`) exactly match the values generated by DuckDB SQL (`features/build_features.sql`).

The SQL rebuild was executed only against a separate scratch database. The original database was opened read-only and was not modified.



## 3. Rounding Issue and Resolution



Three features previously showed differences of +/-0.0001 because Polars and DuckDB used different default rounding behavior.



The Python implementation was updated to use:



```python

.round(4, mode="half_away_from_zero")

```



Affected features:

- `txn_count_change_3m`

- `login_count_change_6m`

- `credit_utilization`
